گزارش پیاده‌سازی Resume Check — جابینجا و معیار سابقه

این قابلیت در خود نرم‌افزار اجرا می‌شود و به AI، API مدل زبانی یا ارسال HTML به دستیار وابسته نیست. مطابق درخواست اولیه، کاربر فایل Excel را انتخاب می‌کند؛ برنامه سپس HTML هر متقاضی را از URL اصلی می‌گیرد، لینک واقعی دانلود را استخراج می‌کند، فایل را دریافت می‌کند و بررسی سابقه و تولید گزارش را خودکار ادامه می‌دهد. HTML ارسال‌شده تنها نمونهٔ پیاده‌سازی و تست بود؛ در برنامه ذخیره یا Hardcode نشده است. کاربر تأیید کرد که انتخاب Excel دستی و تمام مراحل بعدی خودکار باشد.

معیار فناوری‌های موردنیاز، Input و Chips، State، Validation، ارسال API، KeywordsCriterion، match_keywords، normalize_keyword، required_found/required_missing و دو ستون گزارش مربوط به معیار حذف شدند. تنها معیار، حداقل سابقهٔ اعلام‌شده است. قواعد استخراج سابقه و عدم محاسبه از تاریخ‌ها تغییر نکردند. شناسایی فناوری‌ها در گزارش، به‌عنوان قابلیت اطلاع‌رسانی موجود، حفظ شده و بر نتیجه تأثیری ندارد.

UI فارسی و RTL با انتخاب‌گر دو روش، کارت‌های جمع‌وجور کنار هم در دسکتاپ و زیر هم در موبایل، رنگ هماهنگ، حالت Light، فوکوس قابل مشاهده و انیمیشن ظریف تکمیل شد. فونت وزیرمتن همراه برنامه قرار دارد و به CDN خارجی وابسته نیست؛ مجوز OFL همراه فایل است. منبع فونت: https://github.com/rastikerdar/vazirmatn/tree/v33.003

Excel واقعی ارائه‌شده: یک شیت، ۷ ستون و ۵۲۴ متقاضی. عنوان «نام متقاضی» برای نام و Hyperlink واقعی برای لینک استخراج می‌شود؛ موقعیت ثابت ستون یا نام ثابت شیت استفاده نشده است. هر ۵۲۴ نام و URL با سلول ردیف اصلی برابر بودند. Hyperlink، فرمول HYPERLINK با URL لفظی و متن URL پشتیبانی می‌شوند. شناسه داخلی مستقل، شماره ردیف، نام، URL و نام فایل نگهداری می‌شوند. سقف Excel جابینجا ۲۰۰۰ متقاضی است؛ سقف پوشهٔ فعلی ۵۰۰ فایل باقی مانده است.

HTML واقعی ارائه‌شده: یک لینک با متن «دانلود» و کلاس btn btn-default، به mstorage2.jobinjacdn.com. کد همان href را استخراج می‌کند و Query را دستکاری نمی‌کند. Jobinja و زیردامنه‌های jobinjacdn.com مجاز هستند؛ Redirectها و مقصدهای خصوصی اعتبارسنجی می‌شوند. درخواست‌ها با تنظیمات Proxy سیستم، هدرهای مرورگر و زبان فارسی، پشتیبانی gzip با سقف حجم و نشست کوکی موقت مستقل برای هر متقاضی انجام می‌شوند. نشست بین Redirectها و دانلود حفظ و پس از هر متقاضی کنار گذاشته می‌شود. Referer بین دامنه‌های متفاوت فقط مبدأ صفحه است تا Query امضاشده ارسال نشود. اتصال دریافت واقعی باید طبق توضیح کاربر از داخل ایران باشد.

بررسی پاسخ عمومی مسیر اشتراک با شناسهٔ ساختگی، صفحهٔ انتقال JavaScript دارای __arcsjs و __arcsjsc و دو script را نشان داد؛ ساختار و حجم آن با لاگ کاربر مطابقت داشت. هنگام شناسایی همین صفحه، Playwright مرورگر Chrome یا Edge نصب‌شده را با پروفایل مستقل و بدون پنجره اجرا می‌کند. پس از اجرای JavaScript و پیدا شدن لینک دانلود، کوکی‌ها به مسیر دانلود موجود منتقل می‌شوند. مرورگر و پروفایل شخصی کاربر استفاده نمی‌شوند؛ مرورگر جدید نیز خودکار نصب نمی‌شود. نبود Chrome/Edge خطای واضح دارد. درخواست‌های مرورگر و تک‌تک Redirectها پیش از ارسال با همان قواعد دامنه و DNS بررسی می‌شوند. Service Worker و WebSocket بسته‌اند. Login اضافه نشده است. ماژول jobinja_challenge چالش کوکی را بدون مرورگر حل می‌کند (ارزیابی دو رشتهٔ مبهم و ست کردن کوکی‌های __arcsjs/__arcsjsc)؛ مرورگر فقط fallback باقی مانده است. playwright==1.55.0 از requirements runtime به requirements-dev منتقل شد و spec فقط وقتی Playwright نصب باشد آن را بسته‌بندی می‌کند، چون بسته‌بندی همیشگی آن درایور ~۱۵۰ مگابایتی Node را وارد بیلد ویندوز/لینوکس می‌کرد و همان بیلدها شکست می‌خوردند. نبود Playwright فقط fallback مرورگر را از کار می‌اندازد و پیام روشن می‌دهد. دانلود واقعی با لینک متقاضی هنوز از داخل ایران آزمایش نشده است.

فایل با محتوای واقعی PDF یا DOCX اعتبارسنجی و با نام یکتا در فضای کاری ذخیره می‌شود. فقط فایل‌های دریافت‌شده به runner موجود داده می‌شوند؛ فایل ناقص ناشی از خطای دیسک ارزیابی نمی‌شود. UI شمارش واقعی مرحله دریافت را نمایش می‌دهد، سپس به Progress بررسی موجود می‌رود. دکمهٔ «جابینجا» URL دقیق همان ردیف را با target=_blank و rel=noopener noreferrer باز می‌کند؛ مشاهده رزومه همچنان مستقل است.

خطاهای دریافت اکنون گزارش چندخطی مراحل را در همان قسمت «جزئیات خطاها و گزارش دریافت» نمایش می‌دهند: دامنه، فعال بودن Proxy سیستم، بررسی DNS، وضعیت HTTP و Redirect، نوع/فشرده‌سازی/حجم پاسخ، تعداد لینک‌های دانلود و نشانه‌های احتمالی ورود یا چالش مرورگر. خطای شبکه شامل نوع خطا، errno و کد تأیید TLS است. مسیر و Query لینک، کوکی، متن خام HTML و محتوای رزومه وارد گزارش نمی‌شوند. گزارش از مسیر موجود reason در API و Excel عبور می‌کند و در UI به‌صورت متن قابل انتخاب و کپی نمایش داده می‌شود؛ نشانه‌های HTML تشخیص قطعی علت نیستند.

گزارش دارای لینک جابینجا و شیت «دریافت رزومه‌ها» است. خطای دریافت در ستون مستقل ثبت می‌شود و نتیجهٔ سابقه برای آن خالی می‌ماند. ZIP شامل تمام فایل‌های دریافت و پردازش‌شده از هر سه وضعیت است. فایل‌های اصلی و گزارش‌های قبلی تغییر داده نشدند.

تست‌های محدود: ۶۳ تست Backend مرتبط پاس شد و ۱۲۲ تست نامرتبط انتخاب نشد؛ ۱۶ تست Frontend مربوط به انتخاب منبع، حداقل سابقه، لینک هر ردیف، Progress و دانلود ZIP پاس شد. هیچ Full Test Suite اجرا نشد. نمونهٔ Excel و HTML واقعی فقط محلی بررسی شدند؛ بازپخش HTML واقعی با فایل DOCX ساختگی، بدون درخواست شبکه، همان href کامل را نگه داشت. ساختار واقعی ۵۲۴ ردیفی و دامنهٔ CDN با نمونه‌های ساختگی در تست‌ها پوشش دارند.

تست یک لینک واقعی با اجازهٔ کاربر از محیط خارج ایران موفق نشد و موفقیت دانلود اعلام نشده است. پس از توضیح کاربر دربارهٔ الزام ایران، درخواست واقعی دیگری ارسال نشد. هیچ رزومهٔ واقعی دانلود یا ارزیابی نشد. تست سرتاسری دانلود واقعی از داخل ایران هنوز انجام نشده است.

Build واقعی macOS با PyInstaller آماده شد و Smoke محدود آن ZIPهای ۴۳ رزومه‌ای و دسته‌های وضعیت را از API باز و استخراج کرد، CRC و برابری بایت‌ها را بررسی کرد، و API جابینجا و گزارش دریافت ناموفق و فونت بسته‌بندی‌شده را آزمود. این Smoke با فایل‌های ساختگی و بدون اتصال به جابینجا اجرا می‌شود. نتیجهٔ آخرین اجرا در /tmp/resume-check-jobinja-packaged-verification.log و Build در /tmp/resume-check-jobinja-dist/ResumeCheck.app است. Build جدید هر سه سیستم‌عامل برای انتشار لازم است. Windows/Linux در این نشست Build و اجرا نشدند؛ workflow محدود ویندوز آماده است ولی اجرا نشده است.

- source/frontend/js/app_setup.js — Upload Excel و شروع خودکار

- source/frontend/tests/setup.test.cjs — جایگزین setup.test.js و تست روش جدید
